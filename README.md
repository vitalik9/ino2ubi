# Обновление числовых параметров // par (C++ U/L/UL/ULL)

- Исправлена ошибка «Некорректное целочисленное значение параметра HoldTimeMs: 60000UL» в Code Professional.
- Code Basic и Code Professional теперь записывают в числовое поле SIXX нормализованное десятичное значение `60000` без суффикса; исходный Arduino-код `60000UL` не меняется.
- Поддерживаются целочисленные суффиксы C++ `U`, `L`, `UL`, `LU`, `LL`, `ULL`, `LLU` в допустимом регистре, десятичные/шестнадцатеричные/двоичные/восьмеричные литералы и разделители цифр.
- Проверяется диапазон исходного типа (`unsigned long`: 0–4294967295, `uint8_t`: 0–255, `int16_t`: −32768…32767 и т. д.); `int` считается 16-битным для Arduino AVR и 32-битным для ESP32.
- Диагностика неправильного значения показывает строку объявления `// par`, когда оно присутствует в исходном скетче.
- Сохранена предыдущая поддержка BLE; целевая компиляция в FLProg по-прежнему требует проверки пользователем.

Тесты: `node tests/numeric-regression.js` и `node tests/ble-regression.js`.

# ino2ubi — поддержка BLE callback на ESP32 Core 2.0.17

Эта сборка подготовлена **на основе архива `ino2ubi.zip`, переданного пользователем**. Существующая функциональность конвертера сохранена; добавлена целевая обработка BLE callback.

## BLE: исправления и ограничения

- для класса вида `class X : public BLEAdvertisedDeviceCallbacks` с одним глобальным объектом `X instance;` сохраняются определение класса, методы и объект в **одном именованном** объявлении Code Basic;
- внутренние переменные `// variable`, используемые BLE callback, переносятся перед объявлением класса в том же фрагменте C++, чтобы FLProg не разорвал объявление и место использования;
- значения `// par` внутри callback читаются через отдельные глобальные копии нужного типа, которые обновляются в `setup()` и `loop()`; для `String` обновление выполняется при изменении значения;
- совместимые с известным API исправления `std::string addr = device.getAddress().toString();` и вызова `.c_str()` у строкового литерала внутри BLE callback выполняются при генерации, исходный редактор при этом не изменяется;
- неподдерживаемые классы, прямые обращения callback к контактам FLProg, использование `blePresenceScanner` без объявления и опасные строковые выражения **вне** поддерживаемого callback дают диагностические ошибки с номером строки, если позиция определима;
- BLE-блок в Code Basic помечается как **однократно используемый**, поскольку сканер и callback могут владеть общими ресурсами ESP32;
- Код Professional содержит аналогичный C++-фрагмент, но **импорт и компиляция реального BLE-блока в FLProg для обоих режимов не выполнялись**.

**Границы поддержки:** не является универсальным C++-компилятором/парсером. Поддерживается один простой глобальный `BLEAdvertisedDeviceCallbacks`-наследник и один глобальный экземпляр; вложенные или сложные классы, несколько BLE обработчиков и прямое обращение из callback к `// in` / `// out` блокируются для предотвращения ошибочного экспорта. Изменять MAC-параметры одновременно с активным BLE callback нежелательно; переменные `String` не обеспечивают полноценную межъядерную синхронизацию. Для реальной надёжности требуется проверка на устройстве и целевом FLProg.

**Проверка:** `node tests/ble-regression.js` (тестовые данные MAC анонимизированы). Тесты проверяют анализ, генерацию и ссылки SIXX, но **не** заменяют реальный импорт/компиляцию в FLProg или испытание на ESP32.

### Когда создаётся `.hpp`

- обычные вспомогательные функции включаются прямо в `.ubi`, без генерации лишнего `.hpp`;
- отдельный `.hpp` добавляется только если его содержимое явно передано через поле библиотеки или загружено пользователем;
- если нужен собственный класс/драйвер, загрузите его `.hpp`/`.h` через поле загрузки, либо вставьте его код в текстовое поле; файл будет добавлен в ZIP;
- существующие внешние `#include "имя.hpp"` не подменяются пустыми библиотеками: если исходников нет, зависимость перечисляется в README.txt архива и её необходимо установить отдельно;
- если `.hpp` не требуется, архив содержит только `.ubi` и `README.txt`.

## FIX14 — параметр String в Code Basic и Code Professional

При подстановке параметра `String foo = "text"; // par` FLProg может передать
в код строковый литерал `"text"`. Выражения `foo.c_str()` и сравнение
`foo != activeString` тогда могут не скомпилироваться. В FIX14 введена
**одна общая обработка** `string-params.js`, вызываемая обоими генераторами:

- после разбора кода находятся именно строковые параметры роли `// par`;
- в `setup()`, `loop()` и вспомогательных функциях используются локальные
  переменные типа `String`, создаваемые из параметра при каждом исполнении;
- комментарии, строковые литералы, обращения к полям, директивы препроцессора
  и одноимённые формальные аргументы функций не изменяются;
- выходные `.ubi` сохраняют прежний формат и таблицу параметров;
- скетчи без строковых `// par` не получают новой трансформации.

Пример итогового кода после подстановки параметра FLProg:

```cpp
{
  String __ino2ubi_string_nvsNamespace = "sntp_cfg";
  prefs.begin(__ino2ubi_string_nvsNamespace.c_str(), true);
}
```

**Проверка:** оба генератора прошли тест XML, проверки SIXX id/idref,
регрессионный пример с числовыми параметрами и тест преобразования SNTP.
Импорт и компиляция FIX14 в FLProg 9.8.0 ещё не проверены. Не изменяются
глобальные объявления, дополнительные внешние заголовки и RemoteXY.
Перед обновлением GitHub Pages сохраните рабочую v2.16 FIX13; новую версию
сначала проверьте на тестовых блоках в Code Basic и Code Professional.

## FIX17 — экспериментальная защита числовых параметров // par

Для числовых параметров (`int`, `uint16_t`, `float` и т. п.) в секциях
`setup()`, `loop()` и во вспомогательных функциях добавляется локальный снимок
значения: `auto __ino2ubi_numeric_keepAlive = keepAlive;`.
Далее все обращения в данной секции используют этот снимок. Преобразование
делается лексически, не затрагивая комментарии и строковые литералы.
Это позволяет вынести повторные числовые подстановки, включая приведение
`(uint16_t)keepAlive`, в одно место для FLProg. Строковая защита FIX14–FIX16
и имена параметров Code Basic сохранены.

ВНИМАНИЕ: если FLProg вообще не заменит токен параметра `keepAlive`, ошибка
может переместиться в инициализатор снимка `auto ... = keepAlive;`.
Тогда нужен готовый `.ubi` и итоговый `.ino` для точной диагностики
сериализации параметров. Генерация и статические тесты НЕ заменяют компиляцию
в FLProg 9.8.0. Сначала проверяйте FIX17 в тестовом проекте.

- **Code Professional:** декодируются текстовые фрагменты и редакторские теги `setup`/`loop`, проверяются подключения, сигнатуры и тела функций и присутствие BLE-класса. Это **не полноценная проверка** всего графа Code Professional после обработки FLProg.
- **RemoteXY:** отдельная сверка с исходным скетчем пока не реализована; остаются прежние проверки XML и SIXX-ссылок.
- Если обнаружено расхождение, скачивание отключено, а описание появляется в панели «Сверка .ino → .ubi». Преобразования параметров и адресов считаются допустимыми, если сохраняется значение в SIXX.
- Сверка структурная и **не гарантирует** эквивалентность C++ после работы FLProg, компиляцию, отсутствие ошибок выполнения или отсутствие пропусков в самом Arduino-парсере. После импорта проверяйте созданный проект в FLProg и реальные блоки на оборудовании.

Ручные браузерные тесты: `python tests/roundtrip-browser.py` и `python tests/roundtrip-mutations.py` (требуется Playwright и Chromium).

## UIID — изоляция переменных при повторном использовании блока (2026-11-09)

В Code Professional внутренние переменные с ролью `variable` получают штатный
тег FLProg `UserCodeMultiBlockUseInCodeUUIDTag` после имени (`counter_` + UUID
экземпляра). Дополнительно этот тег применяется к простым `static` и массивным
глобальным объявлениям из `static_declarations` и к простым объявлениям из
`extra_declarations`, а также к их обращениям в секциях кода. Это позволяет
нескольким экземплярам блока иметь независимое внутреннее состояние.

Входы, выходы, пользовательские параметры, макросы и внешние API не переименовываются.
Для Code Basic логика имён не изменена; там используются собственные правила
FLProg для переменных секции declare. Общие аппаратные ресурсы (Wi-Fi, BLE,
Serial, GPIO) и произвольные функции/классы не становятся независимыми только
от добавления UIID. Фактическую компиляцию с двумя блоками необходимо проверить
в установленной FLProg.

Проверка: `python tests/uiid-regression.py`.
