# RemoteXY EditTime regression fix — 2026-11-20

Basis: `ino2ubi-main-remotexy-preferences-no-duplicate.zip`.

## Reproduced failure
A source generated by the RemoteXY V21 editor contains a 51-byte interface configuration and the fields:

- `uint8_t editTime_01_hour;`
- `uint8_t editTime_01_minute;`
- `RemoteXYType_Notification notification_01;`
- `RemoteXYType_RealTimeNet realTime_01;`

FLProg Code Professional treated names shared by RemoteXY struct members and FLProg contacts as contacts even inside the struct declaration. The compiled result referred to missing struct members `editTime_01_hour` and `editTime_01_minute`.

## Change
- In `remotexy.js`, native fields use a private `rxyField_` prefix in the C++ struct, preserving *field order and types* required by the RemoteXY binary protocol.
- All C++ accesses to the native struct now use prefixed members. FLProg contacts retain the original names.
- Removed the redundant upper-bound check on Cloud port after the parameter is represented as uint16_t.
- Added `tests/remotexy-edit-time-regression.js` using the original 51-byte configuration; token replaced with an inert fixture.
- Kept existing Cloud connection, notifications, NVS persistence and EEPROM policies unchanged.

## Validation
- `node --check remotexy.js` passed.
- RemoteXY adapter, Cloud, NVS, and EditTime regression tests passed.
- Integration with actual FLProg 9.8.0/9.8.6 and device flashing **not tested** here.
- The compiler warning about packed non-POD `RemoteXYType_Notification` remains and requires independent layout/API verification against the exact installed library version.
