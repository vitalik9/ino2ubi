# ino2ubi — обновление отображения диагностики HTTP

## Назначение

В отчёте проверки ESP32 Core 2.0.17 одно действие HTTP могло порождать одновременно подробное предупреждение и общий `BLOCKING-IO`; ещё одно сводное сообщение повторяло сведения о нескольких операциях.

## Исправлено

- интерфейс выводит подробное предупреждение `http.POST()` / `http.getString()` вместо дублирующего `BLOCKING-IO` для того же вызова;
- при полном наличии подробных сообщений избыточная сводка о нескольких сетевых вызовах не отображается;
- количество предупреждений в заголовке соответствует реально показанным карточкам;
- уточнены рекомендации для чтения тела HTTP-ответа;
- отдельные операции `pulseIn()`, `readStringUntil()` и другие не скрываются, если они не покрыты подробным предупреждением;
- обновлены версии `app.js` и `diagnostics.js` в `index.html`, чтобы избежать использования старых файлов из кеша.

## Не изменялось

Исходные проверки `runtime-safety.js` и `esp32.js`, решения о блокировке экспорта, генераторы Basic/Professional, преобразование `.ino` в `.ubi`, BLE и числовая обработка остались без изменений. Отчёты внутренних анализаторов по-прежнему содержат полные исходные сведения.

## Проверки

- пример с `http.POST()` и `http.getString()`: 4 внутренних предупреждения → 2 отображаемых;
- 7 тестов отображения, включая сохранение отдельного `BLOCKING-IO`;
- пройдены существующие регрессионные тесты BLE (11), преобразования (35), числовых литералов (30) и runtime (19);
- проверен синтаксис всех JavaScript-файлов и HTML-разметка;
- браузерный интеграционный тест не выполнен: навигация Chromium блокируется ограничениями среды;
- тест в установленном FLProg не проводился.
