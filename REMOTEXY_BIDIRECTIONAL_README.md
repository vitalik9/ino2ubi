# RemoteXY — двустороннее управление (экспериментальная сборка)

Основа: `ino2ubi-remotexy-411-library-compat-fix.zip`; ESP32 Arduino Core 2.0.17 / RemoteXY 4.1.11 / Code Professional.

## Новая настройка

При разборе RemoteXY .ino включена галочка **Двустороннее управление** (можно отключить для прежних контактов). Для каждой переменной раздела `// input variables` генерируются:

- `имя` — выход FLProg, последнее значение ESP32/RemoteXY;
- `имя_set` — вход FLProg с новым значением для интерфейса;
- `имя_apply` — вход Bool, запись `имя_set` во внутреннее поле **только по фронту FALSE → TRUE**.

Чтобы отправить следующее изменение, сначала вернуть `имя_apply` в FALSE. Веб-интерфейс подключается к отдельной логике/веб-серверу FLProg и связывается с `имя_set`/`имя_apply`. Конвертер **не создаёт сам веб-сервер**.

## Порядок в цикле

1. Вызов `RemoteXYEngine.handler()` обрабатывает обновления из телефона.
2. Импульс `имя_apply` может обновить то же поле из логики FLProg.
3. Общие значения участвуют в сохранении Preferences (если поле было помечено `Save to EEPROM` в редакторе RemoteXY).
4. Выход `имя` отражает актуальное значение из структуры.

Если телефон и компьютер меняют одно поле почти одновременно, в одном цикле FLProg Apply имеет приоритет (выполняется после `handler()`). Позднейшее изменение с телефона вновь обновит его. Синхронизация интерфейса на телефоне зависит от поведения RemoteXY 4.1.11 и приложения 4.18.03; она пока не испытана на устройстве.

## Сохранены особенности прежнего конвертера

- Wi-Fi запускает отдельный блок FLProg;
- Cloud server/port/token остаются параметрами блока;
- Notification/NotificationNet, Terminal, RealTime остаются в адаптере;
- Preferences хранит только помеченные пользователем поля;
- служебное EEPROM для NotificationNet не отключается;
- один экземпляр RemoteXY, без En.

## Проверка

Тесты `tests/remotexy-*.js` и проверки JS-синтаксиса проходят. Компиляция нового двустороннего .ubi в FLProg и синхронизация на реальном ESP32 не выполнялись. Сначала испытайте два простых поля (switch и float), затем Cloud и push. Перед прошивкой сохраните резервную копию рабочего проекта.
