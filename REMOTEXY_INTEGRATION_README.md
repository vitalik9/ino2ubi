# RemoteXY 4.1.11 — расширенный экспериментальный адаптер INO2UBI

Основа: исходный архив пользователя `ino2ubi-main.zip`. Экспорт: Code Professional `.ubi` для FLProg 9.8.6, ESP32 Arduino Core 2.0.17. В этом выпуске не заявлена поддержка **всех** аппаратных вариантов библиотеки RemoteXY.

## Что обрабатывается

- подключение через FLProg-managed Wi-Fi station, Wi-Fi AP, RemoteXY Cloud;
- стандартные поля интерфейса: `uint8_t`, `int8_t`, `int16_t`, `uint16_t`, `int32_t`, `uint32_t`, `float`, `char[N]`; сохранённая в конфигурации структура и бинарные границы сверяются;
- `RemoteXYType_Notification`, `RemoteXYType_NotificationNet`, `RemoteXYType_Terminal`, `RemoteXYType_RealTime`, `RemoteXYType_RealTimeNet` в новой конфигурации `0xFE`;
- EEPROM-дескрипторы новых конфигураций, включая переменные входа, сохранённые редактором RemoteXY;
- защита от повторной отправки текста в каждом цикле при постоянно активном сигнале.

Для Notification, NotificationNet и Terminal создаются **входы FLProg** `имя_send` (Bool, отправка по переднему фронту) и `имя_text` (String, содержимое уведомления/терминала). Подайте текст на `имя_text` и короткий импульс на `имя_send`. Следующий импульс после возврата в LOW отправит новое сообщение. Не подавайте постоянные импульсы высокой частоты.

Для RealTime и RealTimeNet создаются **выходы FLProg** `имя_utc` (UnsignedLong, Unix-время в секундах; ноль, если не получено) и `имя_valid` (Bool). При значении больше 2106-02-07 UTC 32-битная секунда переполняется. Данные берутся из `getUtcTimeStamp()` RemoteXY.

## Важно для уведомлений

- элемент Notification требует лицензии PRO мобильного приложения;
- `RemoteXYType_Notification` передаёт сообщения при наличии подключения телефона, интернет не обязателен;
- `RemoteXYType_NotificationNet` требует доступа ESP32 к Интернету, включённой EEPROM и первичного получения идентификатора/ключа от телефона;
- при `NotificationNet` адаптер подключает `EEPROM.h` **до** `RemoteXY.h` и выделяет размер EEPROM, рассчитанный библиотекой после `addGui`;
- режим локальной точки доступа AP с NotificationNet отклоняется: адаптер не создаёт Интернет-маршрутизацию;
- для интернет-уведомлений RemoteXY документирует ограничение не чаще одного сообщения в 5 минут;
- сообщения буферизуются библиотекой; слишком длинный текст или переполненный буфер приводят к потере сообщений;
- настройки EEPROM в других блоках FLProg нужно согласовывать вручную, поскольку Arduino ESP32 EEPROM имеет общий ресурс.

## Как использовать

1. Выберите профиль ESP32 Core 2.0.17.
2. Скопируйте **полный** код из редактора RemoteXY (`RemoteXY_CONF_PROGMEM`, `struct ... RemoteXY`, конфигурация режима).
3. Вставьте код в конвертер, нажмите «Парсить RemoteXY», проверьте контакты и сгенерируйте Code Professional `.ubi`.
4. В FLProg 9.8.6 подключите сеть самостоятельно, импортируйте блок и выполните компиляцию с установленной библиотекой RemoteXY **4.1.11**.
5. Проверьте передачу данных, уведомления при подключённом и отключённом телефоне, повторное включение ESP32 и отсутствие конфликтов EEPROM.

## Неподдерживаемые функции

Адаптер не реализует все аппаратные транспорты RemoteXY: UART/USB, Bluetooth Classic, BLE, Ethernet, внешние ESP8266 AT-модемы, SoftSerial и другие. Нет режима нескольких экземпляров блока и входа `En`. Также не гарантированы кастомные C++ типы, другие форматы конфигурации и произвольная пользовательская логика исходного скетча — интерфейс и сигналы конвертируются, пользовательскую логику следует собирать в FLProg.

## Статус качества

Синтаксис JS и тесты парсинга/адаптера проходят. Сборка `.ubi` используется через штатный Code Professional. Но реальные компиляция в FLProg, проверка библиотек из локальной Arduino IDE, подключение телефона и сквозные push-уведомления **не проведены**. Полные jsdom-тесты недоступны в этом окружении.

Документация: https://docs.remotexy.com/docs/elements/notifications/ ; https://github.com/RemoteXY/RemoteXY-Arduino-library

## Подключение Wi-Fi отдельным блоком FLProg

SSID и пароль из исходного `.ino` игнорируются адаптером и не входят в экспортируемый `.ubi`.
Подключение ESP32 к сети выполняет отдельный Wi-Fi блок FLProg. RemoteXY проверяет
`WiFi.status()` и использует уже установленное соединение; повторно `WiFi.begin()`
не вызывается.

Для режима `REMOTEXY_MODE__WIFI_CLOUD` в параметрах блока доступны:
- `Cloud server` (`remoteXYCloudServer`, String);
- `Cloud port` (`remoteXYCloudPort`, uint16_t, 1–65535);
- `Cloud token` (`remoteXYCloudToken`, String).

Значения по умолчанию берутся из `.ino`; пустые строки сервера и токена допустимы
при импорте, но до их заполнения облачное подключение не создаётся.
Обновление параметров требует повторной инициализации блока (обычно прошивки).
Не публикуйте заполненный токен в открытом репозитории.

## Сохранение интерфейса только в Preferences (NVS)

Для ESP32 Core 2.0.17 конвертер определяет сохранённые поля по исходным
дескрипторам `Save to EEPROM` в конфигурации RemoteXY `0xFE`. После
считывания списка полей генератор удаляет **только эти дескрипторы** из
выходного массива конфигурации: счётчик записей становится нулём, а GUI
байты и дескрипторы сложных переменных не изменяются.

- пользовательские значения сохраняются исключительно через `Preferences.h` в пространстве `rxy-state`;
- запись выполняется только после изменения, через 1000 мс без новых изменений;
- восстановление происходит при запуске контроллера;
- при изменении схемы конфигурации сохранённые значения сбрасываются;
- если присутствует `NotificationNet`, `EEPROM.h`, `getEepromSize()` и `initEeprom()` остаются для внутренних служебных данных RemoteXY;
- без `NotificationNet` EEPROM не инициализируется адаптером.

**Внимание:** корректность модификации двоичной конфигурации подтверждена
структурными тестами генератора, но не компиляцией/испытанием с библиотекой
RemoteXY 4.1.11 на ESP32. Перед использованием на оборудовании проверьте
обновление элементов, рестарт ESP32, повторное облачное соединение и
доставку интернет-уведомлений. Библиотека RemoteXY не модифицируется.
